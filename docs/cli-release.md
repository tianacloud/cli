# CLI release

The default release entry is `.github/workflows/release.yml`. Update
`packaging/npm/package.json` and its lockfile to the chosen version, then push
its `vVERSION` source tag. The workflow tests Linux/macOS/Windows, compiles seven
native Go targets, packs eight npm tarballs and automatically publishes those
artifacts to npm. Prerelease versions use `next`; stable versions use `latest`.
Manual dispatch retains the existing `dry_run` option for checks and recovery.

The main package has seven exact-version optional dependencies. npm selects the
native package by operating system and CPU. Each platform package includes its
executable and build manifest; customers install everything from npm.

## 1.0.0 dependency baseline

Both Go SDK modules (`sdk-go` and `sdk-go-sqlite`) are pinned to `v1.0.0`.
The SQLite SDK's earlier release tags were removed during its history reset;
fresh builds must use the new release. Module checksums are generated by Go.
Source builds and default release scripts report `1.0.0`; explicit release
version overrides remain supported. The main npm package and all seven optional
platform dependencies use the same exact version.

## 0.3.6 lists and credential locations

SQLite, Git and Web lists, including SQLite branch lists, automatically read all
matching pages and print one complete table. They do not wait for `More` input or
print a next cursor. Branch search and an optional `--after` starting cursor remain.

The Go SDK is pinned to the published `v1.0.0` release. Its implementation matches
the previous fixed SDK commit; the SDK repository has replaced its earlier public
history, so the earlier pseudo-version is no longer fetchable by fresh CI builds.

All account readers, native connections and Web previews use
`$XDG_CONFIG_HOME/tiana/credentials.json`, or `~/.config/tiana/credentials.json`
when XDG is unset. A per-file account credential override is no longer supported.
Previously selected custom files are left untouched and are not migrated. If the
default store has no account, sign in again to populate it. Explicit data tokens
and management origin selection retain their existing behavior.

## 0.3.4 environment selection

Unset `TIANA_API_ORIGIN` now selects online regardless of saved accounts.
Staging tasks must pass their explicit origin to every CLI/Git subprocess.
Online uses system roots; explicit staging adds the bundled public root.
See [staging access](staging-ca.md) for browser trust setup.

Pending commands and their locks now use an origin-specific filename. An old
`pending-command.json` is left untouched and is not discovered automatically.
Resolve any interrupted creation with the previous CLI before upgrading:
retrying it as a new command after upgrading can create a duplicate resource.

## Initial setup

The scope owner initializes these public packages:

- `@tianacloud/cli`
- `@tianacloud/cli-darwin-x64`, `@tianacloud/cli-darwin-arm64`
- `@tianacloud/cli-linux-x64`, `@tianacloud/cli-linux-arm64`, `@tianacloud/cli-linux-riscv64`
- `@tianacloud/cli-win32-x64`, `@tianacloud/cli-win32-arm64`

Configure each package's Trusted Publisher as owner `tianacloud`, repository
`cli`, workflow `release.yml`, with direct publication enabled. The publish job
uses GitHub-hosted runners, `id-token: write`, Node.js 24 and npm 11.20.0.
See [npm trusted publishing](https://docs.npmjs.com/trusted-publishers/).
The repository's existing `SDK_READ_TOKEN` reads the pinned Go SDK dependencies.
It is used for dependency download and is excluded from release artifacts.

## Build without publication

Use Go satisfying go.mod, Node.js 20+, npm and access to pinned Go dependencies:

```sh
node scripts/release.mjs VERSION --dry-run
```

This retains seven builds and eight tarballs under `dist/releases/`, with
`npm-release.json` recording each package name, version, filename, size and
integrity. The packager checks executable architecture, verified TLS policy and
manifest SHA-256. Release Go builds use `GOWORK=off` and `-mod=readonly`.

Select an existing matching tag in the workflow's manual dispatch and leave
`dry_run` selected to reproduce source build and artifact installation tests.
Linux/macOS/Windows runners execute their matching package; other architectures
receive build/archive verification until they have native acceptance coverage.

## Publication and recovery

Tag pushes automatically test, build and publish to npm. GitHub Release assets
and published npm versions remain immutable. Retain the exact eight tarballs and
`npm-release.json` for any interrupted or deferred publication.

To publish an existing verified set without rebuilding it, manually dispatch
`Release CLI` with the original tag, `dry_run=false` and `artifact_run_id` set to
the successful original release run. The workflow requires the same repository,
release workflow and source commit, verifies all eight package integrities and
repeats native artifact installation checks before publishing. Leave that input
empty for the normal build path. For 1.0.6, the retained original run is
`40295347181`; its tarballs are also preserved on the GitHub Release.

The workflow preserves the exact tarballs in `cli-npm-release`. It verifies all
existing exact npm versions, publishes seven platform packages and reads back their
integrity, then publishes the main package. Identical existing packages are reused;
conflicting contents require a new version. Publication uses the derived channel.

Retry the failed publication job while the original build artifact is retained.
For manual recovery, download that artifact unchanged and use:

```sh
node scripts/publish-npm.mjs ARTIFACT_DIRECTORY VERSION next
```

Use `latest` for a stable version. npm login or `NPM_TOKEN` is needed for a manual
publication outside Actions. `scripts/npm-token.npmrc` references the environment
variable without saving its contents.

A failed install check after publication leaves the published version in npm;
inspect the exact version and channel before deciding the next release. Reports
must distinguish artifact verification, cross compilation and real native tests.


## 1.0.1 management output and state recovery

The stable release adds JSON for resource lists/details/deletion, SQLite branches,
account status/logout/version and preview startup. SQL keeps its own result format.
Local pending/receipt/update state uses the SDK XDG configuration root; previous
platform pending records require explicit original-path recovery. Login outputs
only verified facts, and publication confirmation separates upload receipts from
current serving checksums. SDK dependencies remain v1.0.0. Release 1.0.1 together
with agent-skills 1.0.2; its CLI minimum is 1.0.1.

## 1.0.2 native SQL boundaries and parse-error recovery

The CLI delegates SQL grammar validation to the App and uses lexical boundaries
for scripts and multiline input. Native vec0/FTS/RTree arguments, aggregate ORDER
BY, bracket identifiers and numeric separators are forwarded without rewriting.
Resource/encoding limits and explicit VACUUM/ATTACH/DETACH restrictions remain.
Scripts stop on the first server error; a later syntax error can follow earlier
autocommit writes. Use explicit transactions when rollback is required.

The immutable SQLite SDK v1.0.1 preserves confirmed sessions/transactions after
SQL_PARSE_ERROR. Core sdk-go stays pinned to v1.0.0. Unknown responses and lost
outcomes remain conservative and never authorize replay. The main and seven
platform npm packages use 1.0.2 and the stable latest channel.

## 1.0.3 tenant file storage

Adds `tiana files list/get/get-url/put/delete`, direct OSS uploads, and file
authorization for local Web previews. Explicit overwrite deletes the existing
object before uploading. Requires the deployed MGR file-storage APIs.

## 1.0.5 singular file command

Use `tiana file list/get/get-url/put/delete` for tenant file storage. Help,
recovery instructions and Skills 1.0.5 examples use the singular command name.
Existing scripts invoking `tiana files` must switch to `tiana file`.

## 1.0.6 unified outbound proxies

All CLI-owned outbound channels share invocation-scoped HTTP/HTTPS CONNECT,
SOCKS5/socks5h, ALL_PROXY and NO_PROXY settings. Port-qualified bypass rules use
the logical Endpoint port even with a physical Gateway override. Target TLS,
credential separation, one route attempt and existing mutation recovery remain
unchanged. PAC, WPAD and OS GUI proxy discovery are outside this release.

Core sdk-go and sdk-go-sqlite both use published v1.0.1 pins. The Go connect helper
receives the proxy snapshot; native children retain their local connection route
and filtered environment. The helper contract remains 3. All package versions,
source defaults and release script defaults are 1.0.6; explicit version overrides
remain supported. Rollback selects a previous immutable CLI release and loses the
new proxy paths, without migrating local state.

## 1.0.7 browser authorization and local auth status

Blocking `login` opens the default browser, while `--no-open` preserves host-owned
URL handling. `login --json` keeps progress on stderr and emits one final result
only after authorization and credential persistence complete. Split start/resume
login remains available to Skills.

`status --auth-only --json` checks local access-token expiry without network,
refresh, quota lookup or local writes. Missing/expired credentials return false;
corrupt or unreadable state returns an error. Ordinary status and WorkBuddy's
quota matching remain unchanged. Credentials and SDK pins do not change.

The main npm package and seven exact native dependencies use 1.0.7. Rollback
selects a previous immutable version and requires removing the new auth-only
command from connector configuration.
